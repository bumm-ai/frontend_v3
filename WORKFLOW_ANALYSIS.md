# Bumm Dashboard — Phased workflow analysis

## System states

### 1. Dashboard state (app root)
```typescript
type DashboardState = 'login' | 'chat'
```
- **login**: Wallet connect screen
- **chat**: Main workspace (chat + editor)

---

### 2. Project status
```typescript
type ProjectStatus = 
  | 'draft'           // Draft, no code yet
  | 'initializing'    // New project initializing
  | 'in-progress'     // Generation / build / audit in progress
  | 'generated'       // Code generated (AI or manual)
  | 'built'           // Contract compiled
  | 'audited'         // Audit passed
  | 'deployed'        // Deployed to Solana
  | 'completed'        // All stages done
```

---

### 3. Action button state
```typescript
type ActionButtonState = 
  | 'inactive'        // No code, button inactive
  | 'review'          // Code present, can run review
  | 'build'          // After review, ready to build
  | 'building'       // Build in progress
  | 'audit'          // After build, ready to audit
  | 'publish'        // After audit, ready to deploy
  | 'publishing'      // Deploy in progress
  | 'upgrade'         // Contract deployed, can upgrade
```

**ActionButtonState transition logic:**
```
inactive → review (when code exists)
review → building → build (after review)
build → audit (after successful build)
audit → publish (after audit)
publish → publishing → upgrade (after deploy)
upgrade → publish (after freeze)
```

---

### 4. Code source
```typescript
type CodeSource = 
  | 'empty'          // Editor empty
  | 'user-input'     // Code pasted/typed by user
  | 'ai-generated'   // Code generated by AI
```

## Full workflow (all stages)

### Workflow 1: AI generation → build → audit → deploy

#### Stage 1: Login & wallet
1. User opens app → `DashboardState: 'login'`
2. Clicks “Connect Wallet”
3. Picks wallet (Phantom, Solflare, etc.)
4. Connected → `DashboardState: 'chat'`

---

#### Stage 2: AI contract generation

**State:** `ProjectStatus: 'initializing' → 'in-progress' → 'generated'`

**Generation stages (8 steps):**
1. Understand user query (~800ms)
2. Identify core features (~1000ms)
3. Build plan (~900ms)
4. Implement contracts (~1500ms)
5. Implement tests (~1200ms)
6. Build project (~1000ms)
7. Run tests (~800ms)

**After generation:**
- Code appears in editor
- `CodeSource: 'ai-generated'`
- `ActionButtonState: 'review'`
- `ProjectStatus: 'generated'`

---

#### Stage 3: Review

**State:** `ActionButtonState: 'review' → 'build'`

**What happens:**
- User clicks “Review”
- Simulated AI code review
- Chat message when review completes
- `ActionButtonState: 'build'`

**Alternative:** User may edit code before review.

---

#### Stage 4: Build

**State:** `ActionButtonState: 'build' → 'building' → 'audit'`  
**Project:** `ProjectStatus: 'generated' → 'in-progress' → 'built'`

**Build stages (6 steps):** analyzing project, generating code, Anchor setup, compiling, tests, optimizing.

**On build error:**
- “Build failed”
- **“Auto-Fix & Rebuild”** + AI auto-fix stage
- Retry build; on success → `ActionButtonState: 'audit'`

**On success:** `ProjectStatus: 'built'`, `ActionButtonState: 'audit'`.

---

#### Stage 5: Audit

**State:** `ActionButtonState: 'audit' → 'publish'`  
**Project:** `ProjectStatus: 'built' → 'audited'`

**Audit stages (6 steps):** preparation, SAST, data/control flow, economic exploit simulation, report, remediation.

**If issues found:** “Rerun Audit with Patches” → apply patches → rebuild → re-audit.

**After rerun:** better score, `ProjectStatus: 'audited'`, `ActionButtonState: 'publish'`.

---

#### Stage 6: Deploy to Solana

**State:** `ActionButtonState: 'publish' → 'publishing' → 'upgrade'`  
**Project:** `ProjectStatus: 'audited' → 'in-progress' → 'deployed'`

**Deploy stages (5):** validation, compilation, upload, deployment, verification.

**On success:** `ProjectStatus: 'deployed'`, `ActionButtonState: 'upgrade'`, contract address stored.

---

### Workflow 2: Custom code → review → build → audit → deploy

1. New project → `ProjectStatus: 'draft'`
2. User pastes code → `CodeSource: 'user-input'`, `ActionButtonState: 'review'`
3. Same stages as Workflow 1 from Review onward.

---

## State transitions

### ActionButtonState (summary)
```
inactive → review → build → building → audit → publish → publishing → upgrade
(building may loop via Auto-Fix; audit may loop via Rerun with Patches)
```

### Project status (summary)
```
draft → initializing → in-progress → generated → built → audited → deployed → completed
```
